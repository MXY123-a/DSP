# Main-Study Freeze Confirmation

For the current CAE-oriented study, the project should now be treated as frozen for participant-facing implementation.

Frozen elements:

- Android intervention build and checksum;
- five DSP-Lab experimental modules;
- five matched conventional control activities;
- Form A pre-test and Form B post-test sequence;
- scoring rules;
- participant-code scheme;
- five-week delivery structure;
- weekly reminder/fidelity framework;
- primary outcome and baseline-adjusted analysis model;
- main exclusion/data-quality rules.

Permitted after freeze:

- correcting a genuine technical fault that prevents study participation, provided the change is dated and documented;
- correcting a safety, privacy, or ethics problem;
- administrative scheduling changes caused by unavoidable institutional events, provided they are logged;
- fixing analysis-code implementation errors that do not change the prespecified statistical question, with the correction documented.

Not permitted merely because interim or final results are disappointing:

- replacing Form B;
- adding a more favorable primary outcome;
- excluding low-performing participants without a prespecified reason;
- redefining completion after seeing outcomes;
- changing the control condition retrospectively;
- selecting a different statistical model solely because it yields a smaller p value.

The next substantive project stage is real classroom implementation and data collection, not additional feature development.
